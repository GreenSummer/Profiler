The module is organized as a thin agent orchestration layer on top of the existing `analysis` package. `llm.py` provides a minimal httpx-based OpenAI-compatible client (`chat_completion`, `probe`) against a configurable base URL (Ollama/vLLM) and raises `LLMUnavailable` on connection failures. `tools.py` defines a read-only, Pydantic-validated tool surface: each tool has an input model (e.g. `GetContextPackIn`, `CompareRunsIn`) whose `model_json_schema()` is registered in the shared `TOOLS_SPEC` list passed to the LLM; `execute_tool` dispatches by name, calls into `..analysis` for all computation, clips results via `_clip` to stay within token budgets, and attaches citations referencing the originating run/report. `context_pack.py` builds compact, deterministic Python-generated digests (`build_run_pack`, `build_comparison_pack`) from the analysis layer — the agent never computes or queries SQL itself. `agent.py` implements the main `chat` loop: it probes the LLM, runs up to `settings.ai_max_tool_rounds` tool-calling rounds, collects citations and optional `view_proposal` payloads, then forces a final answer. If the LLM is unavailable, `offline_answer` falls back to a deterministic rule-based analyst that parses the last user message for keywords and answers from context packs and the findings engine. Dependency direction is strictly one-way: agent → tools/context_pack → analysis; tools never call back into the agent.
