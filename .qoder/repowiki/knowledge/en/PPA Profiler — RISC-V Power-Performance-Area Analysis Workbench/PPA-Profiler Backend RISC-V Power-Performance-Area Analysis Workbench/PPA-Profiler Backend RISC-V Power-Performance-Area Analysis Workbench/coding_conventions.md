- Each API view is implemented as a single function in `analysis.py` named after its plan version (e.g. `list_runs`, `scorecard`, `compare`, `design_space`, `area_explorer`, `timing_explorer`, `perf_explorer`, `hotspot`, `findings`, `ingest_status`) and exposed by a thin route in `main.py`.
- Database access goes exclusively through SQLModel `Session` objects injected via FastAPI `Depends(session_dep)`; routes never import SQLAlchemy directly.
- Configuration is centralized in `config.Settings` using Pydantic `BaseSettings` with `env_prefix = 'PPA_'`, so every runtime value is overridable via `PPA_*` environment variables.
- Report parsers implement a uniform contract returning dataclasses from `parsers.base` (`AreaReport`, `TimingReport`, `PowerReport`, `QorReport`, `PerfReport`) carrying `rows`/`groups`/`metrics` plus a `warnings` list and a `VERSION` constant used by ingest to detect reparsing needs.
- Rule evaluators follow the `_ev_<domain>_<name>(facts, params) -> list[tuple[severity, scope_dict, evidence_dict]]` signature and are registered in the `EVALUATORS` dict keyed by rule id, allowing YAML-driven rule packs to drive pure-Python checks without touching the database.
- Findings are persisted with a stable `rule_id` (e.g. `TIM_WNS_NEG`, `PWR_OVER_BUDGET`, `DQ_MISSING_REPORT`) and a `category` field (`timing|area|power|performance|cross_domain|data_quality`) so they can be filtered and displayed uniformly across the UI.
