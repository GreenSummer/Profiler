The module is organized around a shared result schema and per-tool parser modules. `base.py` defines the immutable dataclass contracts (`AreaReport`, `TimingReport`, `QorReport`, `PowerReport`, `PerfReport` and their row types) that all parsers return; these are the stable interface consumed by downstream ingest code. `common.py` provides reusable string/number helpers (`to_float`, `parse_kv`, `is_number`). Each tool-specific file (`rtla.py`, `primepower.py`, `specint.py`) exposes a single `parse_<tool>(text: str)` function that streams lines, tracks state via simple flags or regex sections, and emits one of the `base.*` report objects. Cross-parser coupling is minimal: `primepower.py` reuses `rtla.ParseError` and normalizes its hierarchy paths to match RTLA spelling so cross-domain joins work, while `specint.py` also reuses `rtla.ParseError`. All parsers follow a line-by-line state machine pattern with sentinel markers (`---`, `=`, section headers) and append unparsable lines to a `warnings` list rather than failing hard, raising a domain `ParseError` only when zero rows are produced.
